# 科研 Vault 工作约定

本文件是个人 AI/ML 科研 Vault 的初始规则模板。发行包中的 ResearchVault 尚未部署；复制到用户选定的正式库后，Zotero 管文献与原 PDF，Obsidian 管知识和项目，Codex 协调研究工作。

## 开始任务

- 先确认用户已指定正式库，禁止默认将发行包模板绑定为插件输出或在其中开展真实入库。正式使用时在库根工作，读取 `research-profile.json` 与相关项目状态；方向未定时保留探索状态。
- 科研任务使用本项目 `.agents/skills/ai-paper-copilot/SKILL.md` 并按需读参考；安装或续装使用 `ai-paper-setup`，先读 `setup-state.json` 与实际配置。尚未安装时定位用户提供的套件，不猜工具已安装；已有 PDF、摘要或段落可直接处理。
- 已授权检查真实环境的首次接入或连接故障，运行技能内 `doctor.py --vault <本库> --json`；它读取本机偏好、检查登录并探测本地 API，但不安装、不上传、不转换。纯文件准备只用结构校验器。MinerU 可暂不配置；需要解析时再明确后端。
- 任务需要全文转换时，已选后端是首选路径；无论云端还是本地，执行全文提取前都必须先针对本篇论文取得一次处理授权。云端且 `upload_policy` 为 `ask_before_upload` 时，还要在上传前实际询问，不能因为尚未授权就静默改走本地提取。
- 已选方式暂停、报错、超时或质量不足时，不自动授权另一方式。切换前让用户选择具体替代方式并等待答复；已有明确备用顺序则按其触发条件执行。`Paused` 且原因未明不等于失败，不自动改本地或重新上传。

## 路径与证据

- 路径以 profile 为准：`01knowledge` 综合，`02vault` 文献笔记，`03fulltext` 原文资料包，`04projects` 项目/实验，`05writing` 稿件，`06inbox` 待整理；模板在 `templates/`，字段说明见 `templates/README.md`。
- 正式文献用 `library_scope + zotero_key` 识别，附件用 `pdf_key`，写作用 `citekey`。身份未知先记录待补，不猜 key，不直接修改 Zotero SQLite。
- 不编造来源、页码、数字、实验或用户判断。关键 claim 留原始位置；解析文本、Agent 核验和用户复核分别记录。
- 初始配置未选择 MinerU 后端；实际使用时核对 profile 的 `upload_policy` 和已有明确授权，选择服务与范围后再上传，不从模板推断授权。

## 写回与执行

- Zotero 插件笔记先导出到 inbox 的 `Zotero导出/`，由主 Codex 核对并合并，不让插件直接覆盖正式文献笔记。
- 文献笔记与知识页用 AI/HUMAN 分区，更新用技能内 `update_ai_note.py`，保留人工区和其他人工正文。文献变更后复位复核状态；知识页变更后明确提示需要人工重核，旧记录不代表新版认可。不把 AI 检查标成人工已复核。
- 用户区的“我的思考”和核查记录由用户维护；没有明确确认不得代填。缺标记、身份冲突或并发修改时先解决当前文件冲突。
- 在明确目标、文件范围与预算内连续推进；新增付费/上传范围、扩大实验资源、删除或发布前说明具体动作并确认。密钥和登录态不写入本库或 Git。
- 交付前运行与本轮文件相关的结构检查；科学证据、实验执行和 LaTeX 编译单独报告真实状态。更新项目下一步，持久成果简记于 `01knowledge/log.md`。
- 默认中文笔记与沟通，保留必要英文术语；正式论文英文，公式 LaTeX。Git commit 信息用中文；新增代码写清晰详细的中文注释。
