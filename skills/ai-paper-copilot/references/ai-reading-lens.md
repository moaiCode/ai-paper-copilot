# 阅读论文与生成完整笔记

默认协作方式：Agent 先读材料、形成完整笔记，用户再复核关键证据和补充个人思考。用户只要速筛或解释局部时按其要求缩小，不强制写长笔记。

## 先看材料能支持什么

- 只有摘要：写研究问题、作者主张、可能的相关性与待取材料。不要补方法细节、实验数字或局限的“合理猜测”。
- 有 PDF：用户明确选择直接阅读，或仅问局部问题时，无须等 Markdown 转换；双栏、公式与图表优先查看原始页面。已选全文解析方式暂停、失败或质量不足后的切换，仍按 [方式切换规则](pdf-materials.md#解析异常与方式切换)先取得选择，不以“材料够用”为由自行换方式。
- 有解析全文：先检查覆盖范围、图像和参考文献是否完整，关键数字和公式按需回 PDF。正文缺失时交付受限草稿并列出缺页。

阅读前查看相关项目当前问题；没有项目时说明暂按通用 AI/ML 视角分析，不杜撰“对我的课题的启发”。

## 完整笔记的内容

使用 `templates/精读笔记模板.md`，AI 区至少覆盖以下内容；论文未涉及的内容写“不适用”或“未披露”，不强填答案：

1. **问题与背景**：任务、既有方法的具体不足、本文的切入点，以及作者报告的贡献。
2. **方法与直觉**：输入到输出的数据流，用一个具体样本解释关键步骤；公式说明变量、目的和假设，保留可靠 LaTeX。
3. **关键设计**：设计选择依赖什么假设，原文是否给出理由；对作者思考路径的重建明确标成推断。
4. **实验与证据**：数据与划分、基线、指标、协议、算力与实现信息；核心 claim 对应哪些图表，哪些限定条件影响解读。
5. **局限与可迁移性**：原文披露的限制、Agent 识别的风险、尚待验证的问题，分别表述。
6. **下一步**：值得查哪篇相关论文、验证哪个最小问题、需要什么代码或材料。无依据时不承诺“一周单卡必能复现”。

少量核心主张放入 frontmatter `claims`，并在正文引用 `C1` 等编号。其他解释用正常段落、列表或小表格，不把笔记做成大量空字段。

## AI/ML 评估透镜

按论文类型选择相关项：

| 方面 | 要检查的实际问题 |
|---|---|
| 任务与协议 | 任务定义、数据集版本、split、metric、输入尺度、是否 TTA/集成/额外数据 |
| 比较公平性 | 基线版本、调参、训练预算、参数规模、数据与评测条件是否对齐 |
| 数据可靠性 | 数据泄漏、测试集调参、预训练污染等是否有证据支持或尚不可查 |
| 归因 | 消融能排除哪些替代解释，是否同时改变训练时长或规模 |
| 不确定性 | 重复实验、方差、统计方法与论文 claim 的强度是否匹配 |
| 可复现性 | 代码、权重、超参、环境、数据许可、评测命令和已知限制 |

理论论文侧重定义、假设与证明边界；数据集论文侧重采集、标注、偏差与许可；系统或 LLM 论文增加成本、延迟、提示与推理配置。没有这些实验不等于论文不合格。

## 写回与用户复核

- 第一次写入生成 AI/HUMAN 双区笔记，人工区只保留空白思考区和核查清单。
- 存在笔记时按 [更新约定](vault-and-index.md) 使用更新脚本，禁止整文件重写覆盖人工内容。
- Agent 核对核心 claim 后可标 `agent_verified`，笔记仍为 `unreviewed`。告诉用户优先复核哪些图表、限定条件和推断。
- 用户确认部分或全部当前内容后，按其明确范围更新 `partial/reviewed` 及对应 claim；不要把“已读消息”当成复核。
- 最后给出简短导读：本篇讲什么、关键证据在哪、最大的待核项是什么，以及笔记路径。
