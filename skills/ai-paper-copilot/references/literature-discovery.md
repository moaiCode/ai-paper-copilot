# 文献发现、筛选与入库

从用户的研究兴趣或具体问题开始；已有 PDF 可以直接读，正式入库是归档步骤。全流程覆盖探索、筛选和追踪，不承诺一次检索就证明“没人做过”。

## 探索与检索

1. 先读取相关项目当前问题。用户尚无细分方向时，基于兴趣与背景形成少量候选问题，说明研究价值、可用数据、可能方法与验证成本；让用户逐步缩小，不自动锁定方向。
2. 把问题拆成任务、方法、数据/领域、评价指标和同义词，形成可复用检索式。区分“发现方向”的宽检索与“验证新颖性”的定向检索。
3. 使用实际可用的文献检索工具、搜索引擎、出版方与预印本来源；再做参考文献回溯和后续引用追踪。记录检索日期、平台、关键词与覆盖范围，必要时保存到项目目录。
4. 候选列表列题名、作者年份、来源链接/标识、与问题的关系、材料可得性和筛选理由。只看摘要时明确标注，不生成貌似读过全文的结论。

核对预印本与正式版、勘误和补充材料；近年工作与经典工作都可能决定新颖性，不固定“只查近 12 个月”。正式查新时写“在本轮列明的范围内未发现同设定工作”，给出最接近的比较对象和未覆盖来源。

## 导入 Zotero

- 先按 DOI、arXiv ID、规范来源 URL 或题名/作者/年份组合查已有条目。相似题名不能直接判同一篇；版本、正式发表版与附件关系不清时报告候选冲突。
- 用户已明确要求“把这批文献导入指定 collection”时按范围连续执行；纯检索请求不自动批量写入。通过 Connector、官方 API 支持的接口或实际可用工具导入，不修改 `zotero.sqlite`。
- 优先导入规范题录，检查题名、作者、年份、文献类型和 DOI/arXiv。无 DOI 的论文保留真实来源，不伪造标识。
- 附件使用用户提供、开放获取或已有授权渠道；登录受限时交给用户完成，不绕过权限。保留 Zotero 管理的原始附件，不因全文导出删除或移动它。
- 记录实际 `library_scope`、父条目 `zotero_key`、附件 `pdf_key`；多个 PDF 先确认是正文、补充材料还是不同版本。BBT 的 citekey 用于 `.bib`，不要把数字 itemID 当成永久身份。

## 从入库到笔记

Zotero 阅读器批注和 llm-for-zotero 导出的辅助阅读内容可作为线索。插件导出先落到 `06inbox/Zotero导出/`（实际 inbox 路径以 profile 为准），由主 Codex 合并进正式笔记；插件的 AI 总结仍是待核材料，不能代替论文原文证据或冒充用户观点。

1. 用已有 PDF 或按 [全文资料包流程](pdf-materials.md) 准备材料；解析失败时可直接读 PDF 并说明状态。
2. 查同一 `(library_scope, zotero_key)` 是否已有主笔记。已有则更新，不创建另一篇同身份的正式笔记。
3. 生成完整 AI 区与未复核的人工作业区，按 [阅读透镜](ai-reading-lens.md) 写出可核验的核心 claim。
4. 进行本轮文档结构检查，更新相关导航、项目状态与简短成果日志。用户复核后再记录其确认状态。

## 持续跟踪

保存可重复执行的检索式与最后检查日期；用户需要定期追踪时再配置实际支持的自动化，不把文档里的“每周检查”当作已创建提醒。新工作可能改变已有结论时，列出受影响的笔记与知识页，更新 AI 区并提示重新复核。

批量任务按候选发现、确认身份、取得材料、转换、笔记分别报告成功和失败；单篇失败不伪装整批成功，也不无故阻塞其他独立材料。保留可重试入口，避免重复导入。
