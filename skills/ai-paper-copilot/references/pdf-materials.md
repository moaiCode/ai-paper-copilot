# MinerU 转换与独立全文资料包

主路径使用 llm-for-zotero 的 MinerU 功能生成转换缓存，再由本套件导出到 Vault。导出脚本是**本地缓存适配器**，不负责调用云端转换 API，也不会自动上传 PDF。

## 先选解析路径，再处理上传授权

当任务明确要求全文 Markdown、完整精读或正式归档时，`research-profile.json` 中已选择的 `mineru.backend` 是首选路径：`cloud` 优先走云端 MinerU，`local` 优先走已配置的本地/自托管服务。无论云端还是本地，执行全文提取前都必须先针对这篇论文取得一次处理授权；本地处理也不能先静默运行 `pdftotext` 或 Python PDF 提取。询问应说明具体论文、PDF、处理方式、输出范围，以及云端方案的上传范围和可能费用。

`upload_policy: ask_before_upload` 只表示云端上传前还要再次确认上传授权，不能被解释为“先尝试本地工具”。可以在一次结构化问题中提供“授权云端处理 / 授权本地处理 / 暂不处理”选项；用户选择本地即构成本次本地处理授权。用户拒绝云端、选择本地或云端不可用后，才可以明确标注降级到本地 PDF 提取。

局部问答、无需生成独立全文包时可以直接读取 PDF，不因存在云端后端就强制上传。需要全文资料包时，云端解析完成后再运行本页的导出器；导出器只读取现有缓存和源 PDF，不调用 MinerU。

## 首次转换与缓存识别

先按 [首次配置](integrations.md) 选择云端或本地/自托管；确认实际后端可用、材料上传范围和费用边界后再转换。Zotero 数据目录与实际缓存位置以当前环境为准，不硬编码用户主目录。插件版本、缓存形状与后端不同，首次先检查一篇样本。

本套件参考 llm-for-zotero `v3.9.17` 的实现：缓存可能含 `full.md`、图片、页面/布局信息和 `_llm_source.json`；其中 `attachmentKey`、`parentItemKey` 用于核对附件与父条目。数字 itemID 仅是本地标识，不适合跨库永久引用。[MinerU 缓存源码](https://github.com/yilewang/llm-for-zotero/blob/v3.9.17/src/services/mineru/mineruCache.ts)

先核对缓存确实属于指定 PDF；不根据相似题名、修改时间或“最近生成”猜归属。缺少必要身份时让用户选定附件或通过实际 Zotero 接口核查，不编造 key。

## 导出接口

```bash
# 先检查计划；这里只读取现有缓存和源 PDF。
python3 <skill-dir>/scripts/export_fulltext.py \
  --vault <vault> --cache-dir <实际缓存目录> --source-pdf <实际PDF路径> \
  --library-scope users/0 --parent-key ABCD1234 --attachment-key EFGH5678 \
  --dry-run --json
```

确认匹配后去掉 `--dry-run` 导出；可用 `--converter-version` 记录已核实的版本。实际材料未知时不填写示例 key。`--parent-key` / `--attachment-key` 用于提供或核对身份，不应覆盖与缓存冲突的值。已有资料包默认不覆盖；只有明确更新对应附件时使用 `--replace`，并核查变更范围。

资料包位于 `03fulltext/<library_scope>/<pdf_key>/`，例如 `03fulltext/users/0/EFGH5678/`。包内包含逐字节保留的 `full.md`、原 PDF 副本 `source.pdf`、原缓存图像/结构文件、图像导航 `assets.md` 与来源清单 `provenance.json`；实际缺项以导出 JSON 报告为准。笔记 `fulltext_path` 指向该包的 `full.md`。路径和资源应为包内相对引用，使资料包离开 Zotero 缓存后仍能阅读；保留原始缓存作为上游，不反向修改它。

来源清单记录身份、源 PDF/缓存指纹、导出信息、图像与页码映射；`assets.md` 展示原图，不猜测插入正文的位置。同一附件重新转换时核对新旧来源指纹与变更；相同输入重复导出应无变化，不同附件版本使用不同附件 key 归档。多个附件不自动合并为一篇无来源边界的全文。

## 图像、页码与公式的限制

- 插件缓存的 `full.md` 可能移除了原图像嵌入；导出图片和清单不等于已恢复正文每处图像的正确位置。查看导出报告，缺锚点时用图像索引或原 PDF 核查，不编造上下文链接。
- 布局中的 `page_idx` 是从 0 开始的页面索引；只有对应关系已核实时，文件页序才可转换为 `page_idx + 1`。它不自动等于论文印刷页码，也不能凭索引给每段文字加一个猜测的页号。
- 双栏错序、公式上下标、表格合并单元格、脚注和参考文献可能解析不完整。关键数值、表头和公式应回源 PDF 查看。
- 无法确定图像对应哪页或哪段时，保留资源和“位置未核验”的说明。解析成功并不表示内容正确；图片存在也不表示图片引用已经核验。

## 导出后的最小验收

1. 核对父条目、附件身份和源 PDF；资料包能独立打开。
2. 在全文搜一个专业术语，检查开头、中间和结尾均有合理覆盖。
3. 打开至少一个关键图/表页面，核对文字顺序、关键公式与正文对应；所有本地资源链接可解析。
4. 读取导出报告的缺项与警告；缺少布局材料时保留章节/图表定位，不能声称页码已验证。
5. 用真实包路径更新笔记 `fulltext_path` 和 `material_status: parsed`，再按核心 claim 逐项核验。

全文资料包作为原文派生产物，不手工翻译、摘要或替换原文。需要修正解析时记录问题并从上游重转/重导；研究理解与翻译放进笔记。清理缓存前先确认独立资料包完整，不自动删除 Zotero 原附件或转换缓存。
