# 科研工作流安装向导

用户提供项目链接并请求安装时，由你检查、提问、执行和验证。用户不需要自行准备一份长提示词。此 skill 指导安装过程，本身不代替终端、应用操作或账号授权能力。

## 获取安装依据

源码仓库为 [moaiCode/ai-paper-copilot](https://github.com/moaiCode/ai-paper-copilot)。本地有已确认的源码时先读其根 `INSTALL.md` 和适用 `AGENTS.md`；只有本 skill 时，从该仓库取得安装入口及本轮需要的资源。具体软件设置查源码 `00-安装与首次配置.md`；不要求每次先加载全部科研参考。

源码 `ResearchVault/` 是模板。只有用户明确指定的正式库才是部署目标。用户仅询问如何安装时，先解释或给入口，不以讨论代替真实安装授权。

## 对话与继续执行

1. 只读确认当前平台、工具能力和已有组件。能检查的事实直接检查，避免让用户报版本/猜路径；不因扫描而连接尚未授权的真实科研库或服务。
2. 每轮最多问 3 项缺少的关键选择：正式库路径与新建/已有、解析后端及上传范围、尚不明确的安装范围/目标客户端。若当前 Agent 暴露结构化用户提问工具或表单，必须优先调用它并给出互斥选项；不要把可选问题只写成普通编号段落。没有该工具时才使用文本提问，并说明用户可以直接按选项或自然语言回答。复用当前用户已经明确的选择，不从其他机器的历史说明继承授权。
3. 正式位置确认后，按安装请求连续执行普通准备与配置，不反复问“是否继续”。缺少应用控制或需要本人认证时，给一个具体人工步骤，独立工作继续；不把整套教程退回用户。
4. 续装先读正式库 `setup-state.json` 与 profile，核对已完成项并继续 pending 项。没有状态文件的已有库，按实际观察记录，不虚构历史，也不清空重装。

结构化提问是客户端能力，不是仓库 Markdown 能强制打开的界面。Codex、Claude Code、其他 Agent 或普通聊天窗口的呈现可能不同；如果客户端不支持提问工具，看到编号文本属于预期降级行为，不应宣称已经弹出了选择框。

## 文件准备

- 新库从源码运行本 skill 的 `scripts/setup_vault.py --vault <用户确认的绝对路径> --json` 预览，核对目标后加 `--apply`。脚本默认不写文件，不接受凭据；参数细节用 `--help` 和 `INSTALL.md` 核对。
- 它准备完整模板、主 skill 与本安装 skill、profile、`setup-state.json`、`research-vault-entry.md`。成功仅表示 `files_prepared`，依赖、插件、连接和样本仍需完成。
- 已有目录拒绝自动创建/覆盖。接入已有库先备份并比较 AGENTS/profile/模板/同名 skill，按 00 增量合并；保护人工笔记和原有规则。仅安装 skill 时不擅自创建完整科研库。
- 已部署副本不必再次运行新库创建器。需要源码脚本时使用已确认的仓库或重新取得来源，不把正式库的 `.agents` 误作源码根。

## 工具与验收

依次完成适用项：正式库独立 Python 环境、根规则/profile、Obsidian 与主 Agent 的工作目录/技能发现、必要 Zotero 插件、LLM 临时笔记与图片落点、实际 Codex binary/模型/登录/权限、所需 API/MCP、实际项目 bibliography 和可选插件桥接。已有组件和凭据优先复用；不为清单装齐所有可选插件，不为尚无项目创建虚假自动导出。

插件内运行目录与正式库不同；生成的 bridge 文件仅是待安装内容，必须按真实插件目录安装并读回验证。主会话与插件会话分别验收。

新增权限、上传和费用按用户当前明确的授权办理；本人输入 Token、登录和系统确认时直接在对应产品进行，不把秘密写进文本或 Git。保持自动解析关闭，未经具体授权不导入论文或提交云解析。

先用主 skill 的结构校验器检查文件。doctor 虽然只读，仍会读取真实 Zotero 偏好、检查 Codex 登录并探测本地 API；仅在本轮允许真实环境检查时运行，纯文件准备和隔离测试不调用它。然后分别验证已授权的外部工具；结构通过与 `empty_vault` 不能代替模型/解析/图文质量核查。更新正式库的状态文件与简短证据，交付实际完成项、剩余步骤及接续方式，不把文件部署成功写成全套科研环境已安装。
